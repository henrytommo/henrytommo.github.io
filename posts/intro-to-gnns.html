A (very basic!) intro to GNNs

Why Graph Neural Networks?

ML models often use tabular data to make predictions. Which is great if your model is built from tabular data, but not so great when it's not. Instead, some data is better represented by graphs, where a graph consists of edges and nodes. Some examples of data that are difficult to represent in a table, but instead can be described by graphs:

  • Social networks: people are nodes and their connections are edges. There would only be edges between people who know each other
  • Transportation networks: nodes are bus stops/train stations etc, and edges are the routes connecting the stops
  • Molecules (what we're interested in!): atoms are nodes, and edges are bonds

A great place to start is A Gentle Introduction to Graph Neural Networks. I used this as a starting point, and also created an interactive widget inspired by that article with my own GNN - you can find it further down this page.

The basics

A GNN is a machine learning model that takes in some input data and outputs a prediction. In the process of training, the model learns from the structure of the graph to apply to unknown inputs. Let's look at some examples of key graph terminology using the examples from before:

Node
A point on a graph that is connected to other nodes. In the social network exmaple, this would be a person.
Edge
The connector between two nodes. For a social network, this is a relationship between two people.
Directed vs undirected
If an edge is undirected, direction doesn't matter: two people who know each other have an undirected edge between them. If a bus route connects two stops in one direction but not the other, that edge is directed.
Global attributes
Properties of the entire graph. For a molecule, this might be its lipophilicity.

Within GNNs, we have different types of problems:

  • Graph-level: predict a single property of the whole graph (for example, the solubility of a molecule)
  • Node-level: predict a property for a given node (for example, a person's social status)
  • Edge-level: predict a property of a single edge (for example, the relationship between two people)

The simplest GNN

A GNN takes in a graph and outputs a graph, finding relationships without changing connectivity. Most GNNs use a message passing framework, which will be discussed here.

The GNN learns new embeddings for all graph attributes (nodes, edges, global properties), with a separate multi-layer perceptron on each component - this is the GNN layer. Several GNN layers are stacked together, which output the transformed graph. A classification layer may be put on top of this (to transform outputs) and the prediction is output. There is info in both the nodes and edges, and gathering all this information is called "pooling", which is just aggregation.

Message passing

Message passing is how learned embeddings can be made aware of graph connectivity.

  • For each node in a graph, all neighbour node embeddings are aggregated via an aggregate function
  • All pooled messages are passed through an update function
  • Similar to convolution: an element's value is updated via aggregation and processing of neighbour properties. Note that the number of neighbours can vary in a graph
  • By stacking message passing GNN layers, a node can eventually incorporate info across the entire graph. After n layers, a node has info from nodes n edges away

Global representations

For small graphs, there are only a few steps away from all nodes, so messages can be passed. For much larger graphs, this would be too many layers (note also that having too many layers will average properties out over all the different nodes). A way around this is to use a global representation of a graph, sometimes called a context vector, which is connected to all nodes and edges and can be used as a bridge to pass info.

How a GNN works

We'll talk about a Graph Convolutional Network for this example, and use the example of acetic acid.

First, the acetic acid molecule needs to be converted to a graphical representation. We represent it as a graph, where atoms (excluding hydrogen) are nodes, and bonds are connectors.

Setup

We want to represent the nodes as a matrix, and the bonds as a matrix.

So, we have CH3C(=O)OH (SMILES CC(=O)O), and each atom has the following features: atomic_number, degree (total number of bonds, counting bonds to the implicit hydrogens), charge, is_aromatic. So we can represent each atom as follows:

idxatomatomic_numberdegreechargeis_aromaticvector
0CH36400[6, 4, 0, 0]
1C=O (C)6300[6, 3, 0, 0]
2=O8100[8, 1, 0, 0]
3-OH (O)8200[8, 2, 0, 0]

These extra features represent information encoded in the nodes. This node data is represented by a tensor, x, where

x = [[6, 4, 0, 0], [6, 3, 0, 0], [8, 1, 0, 0], [8, 2, 0, 0]] → dimensions = (4, 4)

We've encoded our nodes as a matrix, now for edges.

We have 3 edges (excluding H): C0--C1, C1--O2, C1--O3. As our edges are undirected, we need to represent both directions - the reason for this will become clearer in a little bit.

  • bond 0 - 1 → [0, 1], [1, 0]
  • bond 1 - 2 → [1, 2], [2, 1]
  • bond 1 - 3 → [1, 3], [3, 1]

We represent this with a 6x2 matrix:

edge_indices = [[0, 1], [1, 0], [1, 2], [2, 1], [1, 3], [3, 1]]

As we're using pytorch and py geometric, we need to transform this to the correct format, i.e. a 2x6 matrix where the first row is the source atom and second row is the target atom index. So:

edge_index = [[0, 1, 1, 2, 1, 3], [1, 0, 2, 1, 3, 1]]

You can read it columnwise to get the bonds.

As an aside - we're representing bonds in this source atom/target atom 2xm type matrix. An alternative is to represent the edges as an adjacency matrix, where the index of each atom is along the top and sides, and there's a 0 if no bond and 1 if there is a bond. The obvious downside here is that if you have n atoms in your molecule, you will have an nxn matrix with loads of zeroes. The list way above is more efficient.

Convolution

This is the layer that makes the GNN a GCN. For other graph neural network types, this part will be different. This is the layer where each atom learns about its neighbours.

Some important notes before starting:

  • The atom matrix, x, and edge_index are kept separate
  • edge_index is used as a sort of lookup table so that the atoms can see who their neighbours are, and is NOT mutated
  • x is changed as it learns from its neighbours

1. First, add self-loops (edge_index)

  • the edge_index matrix links different atoms together. Later, this will allow atoms to see the properties and features of adjacent atoms. but, we want each atom to keep its own properties. To do this, we need to add a self-loop, i.e. a bond between an atom and itself. This looks like adding [0, 0], [1, 1] etc to the edge_index and transforming as appropriate.

2. Linear transform (x)

  • x starts as a 4x4 matrix. This step linearly transforms it to a 4xN matrix - similar to a nn, this is where the weights and biases come in
  • The transform is of the form zj = Whj + b, where h represents the original form of matrix x. So, as each row is an atom, it can be thought of as a transform applied to each atom.
  • W and b above are the weights and biases that are learned via backprop later on.
  • The weight matrix that is multiplied by x determines the dimensions of the resultant x x W matrix, often referred to as hidden dimension
  • Same W and b applied to each atom - this is because the atom matrices used as input can be of any size, so must be generic enough to handle this.
  • This step ends up with 4 atoms, but instead of just the first 4 initial features, it can have lots more. These features may not represent physical properties

3. Normalisation coefficients (edge_index)

  • This step computes the mixing weights between atoms. In the first convolution layer, atoms get information from their immediate neighbours. In the next layer, they get information from atoms that are bonded to their immediate neighbours, and so on. In general, the number of convolution layers should be smaller for small molecules, otherwise you risk averaging the properties of all the atoms over each other.
  • The normalisation coefficient is calculated as: norm(i,j) = 1 / √(d̂i × d̂j) where d̂i is the number of neighbours of atom i + 1 (the +1 is for the self loop). Note this is the graph degree, i.e. heavy-atom neighbours only - not the degree feature in the table above, which counts hydrogens too.
  • So for example, atom 0, the CH3 carbon, has d = 1 (1 neighbour), so d̂0 = 2. Atom 1, the C=O carbon, has d = 3 and therefore d̂1 = 4
    • this means that norm(0, 0) = 1/√(2 × 2) = 0.5
    • norm(0,1) = 1/√(2x4) = 0.354
  • These normalisation weights determine how much of each neighbour to aggregate
  • normalisation is an important step - it means that atoms with a high valency don't dominate

4. Aggregate (x)

  • Next, the normalisation coefficients we calculated earlier are used in the aggregation of the features of the atoms and their neighbours. This is done using the formula: hi′ = Σj ∈ N(i) ∪ {i} norm(i,j) · zj
  • i.e., the sum over atom i's neighbours plus itself (feature vector zj after linear transform) multiplied by the norm.
  • So for atom 0 (CH3): neighbours = self + atom 1 h0′ = 0.5 × z0 + 0.354 × z1 i.e. norm(0,0) × z0 + norm(0,1) × z1
  • note - this is where storing the bonds in both directions comes in. With PyG's default source → target flow, the messages arriving at atom i are the edges that END at i, i.e. the second row of edge_index. So atom 0 collects the column [1, 0] and picks up norm(0,1) × z1, while atom 1 collects the column [0, 1] and picks up norm(1,0) × z0. The coefficient is symmetric, norm(i,j) = norm(j,i), so which way round you read it makes no difference - but if only one direction were stored, one of the two atoms would never see the other at all.
  • after aggregation, dimensions remain the same - in this case, 4 x hidden dim of weight matrix W, but it now contains the norm-weighted z-vals of adjacent atoms

5. ReLU + dropout

  • similar to nn, adds non-linearity
  • Dropout: each number has 10% chance of being set to zero. Survivors scaled up to compensate, so that the expected sum stays the same. This happens during training only - at inference dropout is switched off and nothing is scaled.

Steps 1-5 are ONE CONVOLUTION LAYER. Typically, a GNN will have several of these layers. The outputs are: 4 x hidden_dim node matrix + unchanged edge_index

6. Pooling

  • After several convolution layers, we now have 4 transformed atom vectors, with their length equal to the hidden dimension of weight matrix W.
  • However, for the output, we want to combine these 4 atoms to one molecule vector.
  • There are several different types of pooling, but for now we will talk about global mean pool, which averages the atom vectors element-wise.
  • So, we end up with a 1 x hidden_dim vector
  • This is the "molecule fingerprint" learned by GCN
  • note - PyG batches vectors for speed, but they always stay independent

An aside - fusion

  • in some cases, for example my QSAR biodegradation project, I combine the graph with extra tabular features.
  • This can be done by a small 2-layer neural net:
    1. Linear transform: mix tabular and graph vector to a single vector
    2. ReLU
    3. Dropout
    4. Linear transform to map outputs to 1 output, i.e. the prediction.
  • Without extra tabular features, this would just be the one step of mapping the molecule vector to 1 output

7. Output

  • As above, the molecular vector needs to be converted to an output, the type of which depends on whether it's a classification or regression problem. For regression, the final linear layer's output is the prediction directly. For classification, that raw output is the logits; these are converted to probabilities with a sigmoid (binary) or softmax (multi-class). Note that the standard losses (BCEWithLogitsLoss, CrossEntropyLoss) take the logits, not the probabilities.

Training

Steps 1-7 outline one pass of the GCN for one molecule. During training, each labelled molecule will be passed through the GCN, with loss calculated on the predicted outputs vs actual outputs. This is done over many epochs, where the weight matrices at each layer are trained through backpropagation.

The entire GCN is differentiable, and as the layers are in sequence, only one sweep of backpropagation is needed to calculate the gradients for every layer. The optimiser then uses those gradients to update the weights.

Below is an interactive widget to investigate how changing various parameters affects performance of the model. Using the ESOL solubility dataset to predict solubility of a molecule. The graph shows predicted vs actual solubilities. Code can be found in the repo molecular-gnn.

  • Hidden channels: the size of the hidden feature vectors inside the hidden layers
  • Layers: the number of layers the data passes through
  • Learning rate: the step size when updating W and b
  • Weight decay: a type of regularisation - adds a small penalty to the loss function based on weight size, encouraging the network to keep W small
  • Epochs: how many passes of the entire training set through the GNN

Note: every combination was trained ahead of time (3 seeds each), so this is a lookup rather than a live model.
